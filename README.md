# 污染源在线监测与排污总量核算台

运维与环保岗共用的核算台：录排污单位与排放口、管在线设备、盯小时值、算日平均与总量、对许可量、出报表。

## 运行

```
npm install
npm start
```

默认端口 5262（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：单位数量与生产中数量、排放口数量与运行中数量、设备数量与各状态台数、监测数据条数与自动与补录条数、无效标记条数、报表数量与已上报数量、超标排放口数量、年累计排放量与年许可量对照；下面按排放口一行给出本月各指标的月均值、月总量与超标情况。
- **排污单位与排放口**：单位台账（编码、名称、行业、状态、许可证号、许可年起始日）带排放口清单；排放口台账（编码、名称、所属单位、类型、状态、设备数、数据条数），两者都带增改删。
- **在线设备**：设备台账（编号、所属排放口、监测指标、型号、设备状态、校准有效期、数据条数、无效标记条数），带增改删。
- **监测数据**：小时值清单（排放口、设备、指标、时刻、数值、标记、来源、登记人、是否计入、折算后浓度、当时氧含量与流量），支持按排放口、设备、指标、日期与月份筛选，带单条新增、修改与删除。
- **核算与报表**：选定排放口与月份后给出逐日明细（有效小时数、补录小时数、日均浓度、限值、是否超标、当日流量合计）与汇总（月均、月总量、季度总量、季度许可量、年累计、年许可量、超标天数与超标小时数、超标判定），并可生成与查看报表（草稿、已上报、退回）。
- **对外提供**：面向园区、周边社区、上级平台的对外数据链路。先选公开清单（指标多选、时段按小时、排放口多选），预览页给出随包口径说明（有效数据判定、折算公式、日均、总量公式、许可分解、超标口径）与脱敏样例、命中条数；确认后生成批次，数据包（`release-package.json` / `data.csv` / `口径说明.txt`）落盘到 `data/releases/<批次号>/`。另有批次记录、二次校验与别名对齐核查；脱敏规则在本页维护，改动另起版本并逐条留痕。

## 对外提供链路（每一批都有据可查）

1. **公开清单可选**：指标（COD / 氨氮 / 流量 / 氧含量）、起止时刻（按小时含首尾）、排放口（不选为全部）、接收方与用途、操作人。
2. **口径随数据给出**：生成批次时把当前口径参数（量程、基准氧、有效小时门槛、补录上限、限值、超标次数、许可量、总量除数、许可年起始日）定格成不可变版本 `cal-YYYYMMDD-NN`（参数指纹随版本走，参数没变就复用旧版本号），口径的 8 条文字说明与参数快照写进数据包和 `口径说明.txt`。以后设置改动不影响历史批次。
3. **脱敏是可维护的一层**：字段级规则（`hash` 替换为稳定别名 / `drop` 整列剔除 / `keep` 原样保留），覆盖单位、排放口、设备、小时值四类对象的内部编号、备注与登记人。保存改动即另起版本 `msr-NNNN`，旧批次仍按旧版本解释；每次改动在「规则改动留痕」里逐条记录字段、动作前后、操作人与说明。
4. **脱敏但仍可追溯**：别名 = HMAC-SHA256(批次随机 salt, 实体.字段=原值) 取前缀，同批内同一原值别名稳定（外单位可把多份数据对齐到同一排口/设备），跨批 salt 不同无法关联。salt 与「别名↔内部原值」对照表只写入**内部留存**文件 `internal-align.json`（不随包发出，下载按钮单独标注「勿外发」）；外单位拿别名来核对时，用对齐核查反查到内部记录号。
5. **批次记录**：每批记录生成时刻、操作人、接收方/用途、范围（指标/时段/排放口）、口径版本与指纹、脱敏规则版本、数据条数（计入/不计入分列）、数据包与 CSV 的 sha256、内部对照文件 sha256。
6. **二次校验**：① 落盘文件与批次记录的 sha256 比对（同一批导出两次字节一致）；② 用批次定格的口径版本、脱敏版本与 salt 对**当前内部数据**重新构建，与批次 sha256 比对。不一致时按数据包别名定位差异（新增/删除/变化条数），并通过内部对照表还原出内部记录号，直接回答「与内部口径对不对得上」。

对外数据包各节：`manifest`（批次与口径/脱敏版本、条数、文件清单）、`caliber`（口径快照与文字说明）、`maskingRules`（本批所用脱敏规则全文）、`units/outlets/devices`（公开标识与别名）、`rows`（逐小时：实测值、氧含量、流量、折算浓度、是否计入、不计入原因、别名；内部编号、备注、登记人真名不出现）、`daily`（逐日口径明细，含无效原因）、`totals`（时段总量）。

## 口径（页面上的说明与数字都要与本段一致）

1. **有效小时值**：数据标记为有效、设备状态为「正常」、数值合理，三条都满足才计入统计；其中 COD、氨氮等浓度指标要求数值在浓度量程（默认 0 到 500）之内，流量、氧含量等辅助量只要求非负有限（不套浓度量程）。设备处于校准、维护、故障状态，或者数值异常（浓度超量程、为负数等）的，按无效处理（不计入平均、总量与超标判定），页面要显式标出来。
2. **折算浓度**：`折算浓度 = 实测浓度 × (21 − 基准氧含量) / (21 − 实测氧含量)`，基准氧含量默认 8（可在设置里改）；该时刻没有氧含量读数时按基准氧处理（等价于不折算）。所有平均、总量与超标判定都用折算后的浓度。
3. **日平均**：按小时流量加权，`日均 = Σ(折算浓度 × 该小时流量) / Σ该小时流量`；单日有效小时不足（口径按 18 小时）或者补录小时超过上限（默认 6 小时）的，**该日不计入平均与总量**，页面要写明原因。
4. **补录**：允许用相邻有效值补算缺失小时，补录数据要在页面与结果里与原数据区分开；补录超过单日上限时该日按无效处理，不许把补出来的数当真实监测结果用。
5. **月总量**：`每小时排放量(吨) = 折算浓度(mg/L) × 流量(m³/h) × 1000(升每立方米) / 1e9`，月总量是逐小时按时刻配对累加（浓度与流量必须取同一时刻的那一对）；月平均按有数据且有效的天数平均（分母是有效天数，不是当月天数）。季度总量与年累计用同一套公式逐小时累加，不做任何按天外推。
6. **季度与年**：季度总量按季度内逐小时累加；季度许可量按年许可量乘以该季度实际天数占全年天数的比例分解；年累计按许可年（单位台账里的许可年起始日）累计，跨自然年不重置也不带入其他许可年的数据。
7. **超标判定**：日平均超过限值（COD 100、氨氮 15，可改）**或者**小时值超过限值达到 3 次及以上，都算这个月超标；两项都要在页面上分别给出。
8. **不计入统计的情形**：排污单位处于停产状态、或者排放口处于停用状态的时段，其小时值不计入平均与总量，也不参与超标判定（但要保留可查）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/plants | 单位清单（支持 status、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/plants/:id | 详情（含排放口、报表）/ 修改 / 删除 |
| GET / POST | /api/outlets | 排放口清单（支持 plantId、status）/ 新增 |
| PATCH / DELETE | /api/outlets/:id | 修改 / 删除 |
| GET | /api/outlets/:id/summary?month= | 月均、月总量、季度总量与许可、年累计、超标情况、设备清单 |
| GET | /api/outlets/:id/daily?month=&metric= | 逐日明细（有效小时数、补录小时数、日均、限值、是否超标、流量合计） |
| GET | /api/outlets/:id/exceedance?month=&metric= | 超标判定（超标天数、超标小时数、是否超标、月均） |
| GET / POST | /api/devices | 设备清单（支持 outletId、metric、status）/ 新增 |
| PATCH / DELETE | /api/devices/:id | 修改 / 删除 |
| GET / POST | /api/readings | 小时值清单（支持 outletId、deviceId、metric、day、month、limit）/ 新增 |
| PATCH / DELETE | /api/readings/:id | 修改 / 删除 |
| GET / POST | /api/reports | 报表清单 / 新建 |
| GET / PATCH | /api/reports/:id | 报表详情（含各排放口的汇总与逐日明细）/ 改状态 |
| GET | /api/caliber/current | 当前口径预览（版本号未定稿时标注；不登记新版本） |
| GET / PATCH | /api/masking-rules | 脱敏规则（当前版本、版本史、可维护字段清单与动作）/ 保存为新版本（无变化 409，改动留痕） |
| GET | /api/masking-rule-changes | 脱敏规则改动留痕（字段、动作前后、操作人、说明） |
| POST | /api/releases/preview | 公开清单预览：口径说明、脱敏样例、排放口/设备/条数（计入与不计入分列） |
| GET / POST | /api/releases | 批次清单 / 生成批次（定格口径与规则、数据包与内部对照表落盘、记 sha256） |
| GET | /api/releases/:id | 批次详情（含随包口径说明与规则） |
| GET | /api/releases/:id/download?file= | package=JSON 数据包 / csv=data.csv / note=口径说明.txt / internal=内部对照表（勿外发） |
| POST | /api/releases/:id/verify | 二次校验：文件完整性 + 用定格版本对当前内部数据复算（不一致给差异与内部记录号） |
| POST | /api/releases/:id/align | 别名对齐反查：入参 `{"aliases":[...]}`，返回对应内部原值 |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
